# Source-aware CPU baker verification

Scope: core #56 and ADR 0023. The C++ entry point consumes decoded, caller-resolved
inputs. Native imported document baking, Apple adoption and textured export are
not enabled by this stage.

## Local gates

The initial contract failed to compile on the missing header before implementation.
All 43 CTest contracts passed in Debug and separately with ASan/UBSan. Local macOS
uses `ASAN_OPTIONS=detect_leaks=0` and
`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`; Linux hosted CI retains leak
detection. Exact-head automated review and every hosted matrix check remain merge
gates. SwiftPM static-product build, manifest lint, root-config formatting of all
native/test files and new domain files, whitespace checks and Qt-boundary scans
passed. Inherited compiler warnings and the existing SwiftPM native-build-system
deprecation remain; no warning-free whole-core claim is made.

Clang instrumentation for `source_texture_baker.cc` reports 403/403 executable
lines, 24/24 functions, 386/387 regions and 300/332 branches. The measurement is scoped
to the new implementation and does not assert whole-engine or 100% branch coverage.

## Independent behavior contracts

- Known numerical sRGB values prove imported texture, linear base-color factor and
  vertex colors multiply once. Encoded vertex colors decode before interpolation.
  Independent barycentric red/green/blue values and reversed winding prove corner
  association. Emissive RGB remains independent of base color; scalar maps retain
  metallic/roughness factors.
- Repeated authored UV derivatives choose the expected linear-light mip. Negative
  constant UVs preserve repeat sampling. Textured sources without UVs fail; a
  textureless source does not need fabricated authored coordinates.
- Opaque forces alpha one, mask/blend retain combined straight alpha, and cutoff/
  double-sided policy stays original-triangle aligned. Alpha-zero colored texels
  keep hidden RGB during rasterization and gutter dilation.
- Mixed procedural/imported charts preserve legacy encoded color/alpha and scalar
  pixels alongside imported maps. Legacy normal transposition swaps/negates XY
  according to the top-down tangent basis. Imports use flat tangent normals.
- Exact owned quota succeeds; one byte less fails. Work/chart/material ceilings,
  cancellation, absent owners, moved-from sampler views, invalid enums/factors,
  nonfinite coordinates, malformed image spans, overlapping charts, shared pixel
  claims, degenerate mappings and insufficient texel resolution fail with typed
  errors rather than partial output. Unknown procedural policy remains explicit.
- Synthetic MIT ImportedSurface.ds3 is decoded by readDocument, generated by
  MeshGenerator, mapped by SourceUvAtlasBuilder and baked with actual generated
  corner colors/material factors and a synthetic decoded image. Four aligned
  policies and owned map storage are verified. This isolates the decoder boundary;
  it does not claim PNG decoding or an enabled native document-bake API.

## Reproduction and acceptance limits

Use README CMake configure/build/CTest commands and repeat with
`-DDUST3D_ENABLE_SANITIZERS=ON`, using the platform-supported environment above.
Run `swift build --build-system native -j 4`, manifest lint and root-config
clang-format on new domain and existing native/test sources. A pure library stage
has no app screenshot requirement.

Output quota excludes inputs, allocator metadata and temporary overlap/coverage/
dilation workspace. Texel-work quotas are cumulative operations, not a wall-time or
RSS bound. Each imported triangle must cover an output texel in every enabled map;
very small charts fail explicitly instead of disappearing. Per-triangle chart
utilization and large-model performance remain acceptance work. Native adoption
must resolve decoded image ownership and samplers, preserve final float-filtered
triangle order, publish bounded owned output and integrate Apple rendering/exports.
Independent textured re-import remains required. Core #41 and Apple #143 stay open.
